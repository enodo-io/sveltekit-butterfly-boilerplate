# Static route → add to sitemap + feed

## 1. Add to sitemap (back-office)

Sitemaps are generated by the Butterfly public API (Sitemap plugin, `/v1/sitemaps/{file}`) and relayed by `src/routes/sitemaps/[file]/+server.ts`. There is no sitemap code in the front: after creating a static route (e.g. `src/routes/legal/+page.svelte`), add it in the back-office → Plugins → Sitemap → the `static` sitemap (`pages`) → « URLs ».

### What goes here

Routes that are **not** fetched from the CMS API — i.e. pure SvelteKit pages with no dynamic parameters.

- ✅ `/legal`, `/faq`, `/contact`, `/newsletter` → add to the static URLs
- ✅ `/articles`, `/tags`, `/authors`, `/rss.html`, `/` → already there (keep as reference)
- ❌ `/search`: always `noindex`, it has nothing to do in a sitemap
- ❌ CMS-backed pages (post type `page`) → covered by the `include` posts filter of the static sitemap

A URL entry: `{ loc: '/legal', lastmod?: 'YYYY-MM-DD' }`. Leave `lastmod` out rather than inventing one: it is the only field Google reads, and only while it is accurate. `priority` and `changefreq` are accepted by the plugin but **ignored by Google** — don't spend time tuning them. `{year}` in `loc` with `years: { from }` expands to one URL per year.

A running server serves the result: `curl -s localhost:4173/sitemaps/index.xml` (`/sitemap.xml` 301s to it).

## 2. Create a feed (content listing routes only)

If the route lists multiple content items (taxonomy listings, author pages, section indexes…), also create a feed alongside it. Every feed goes through **`src/lib/server/feed.ts`**:

| Export                               | Role                                                                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `feedSettings(fetch)`                | the property (site title, description)                                                                                                                                |
| `feedPosts(fetch, filter?)`          | the 20 latest posts, `types: '-page'` + your filter, **sorted by `-publishedAt`** (readers and Google News expect chronological items; sorting by update made old posts jump) |
| `feedResponse({ format, settings, posts, title, description, path, feedPath })` | builds the RSS 2.0 / Atom 1.0 document: items with title, link, resume, publication date, thumbnail (640px), authors as **name + profile URL, never the email**; `Content-Type` `application/rss+xml` / `application/atom+xml`, `Cache-Control: CACHE_CONTROL.short`, no `Expires` |
| `feedError(err)`                     | rethrows SvelteKit errors/redirects, `ApiError` → `error(status)`, `RedirectError` → `redirect`, anything else a logged 500                                           |

`FeedFormat` is `'rss' | 'atom'`: the `[format=feed]` matcher accepts these two only. There is **no JSON feed** (it was advertised and 404ed).

**Existing examples:**

- `src/routes/[format=feed]/index.xml/+server.ts` — global feed
- `src/routes/[format=feed]/tags/[id].xml/+server.ts` — per-tag feed
- `src/routes/[format=feed]/authors/[id].xml/+server.ts` — per-author feed
- `src/routes/[format=feed]/sections/[...path].xml/+server.ts` — per-section feed

### Minimal endpoint

```ts
// src/routes/[format=feed]/themes/[id].xml/+server.ts
import api from '$lib/api';
import {
  feedError,
  feedPosts,
  feedResponse,
  feedSettings,
  type FeedFormat,
} from '$lib/server/feed';

import type { RequestHandler } from './$types';
import type * as Butterfly from '@enodo/butterfly-ts';

export const GET: RequestHandler = async ({ fetch, params }) => {
  try {
    const [settings, term, posts] = await Promise.all([
      feedSettings(fetch),
      api.get<Butterfly.Term>({ fetch, endpoint: 'taxonomies/themes/relationships/terms', id: params.id }),
      feedPosts(fetch, { 'terms<themes>': params.id }),
    ]);
    const { name, description } = term.data.attributes;
    return feedResponse({
      format: params.format as FeedFormat,
      settings,
      posts,
      title: name,
      description: description || `All news about "${name}" on ${settings.data.attributes.title}`,
      path: `/themes/${term.data.id}`, // the HTML page of the feed
      feedPath: `themes/${term.data.id}`, // served at /rss/… and /atom/….xml
    });
  } catch (err) {
    feedError(err);
  }
};
```

Then advertise it: `+layout.svelte` emits the `<link rel="alternate" type="application/{rss|atom}+xml">` per `content.type` (add a branch for the new type), and `/rss.html` / `/atom.html` (`src/routes/[format=feed].html/`) list the sections, authors and tags feeds.
